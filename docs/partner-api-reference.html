Partner Portal API Reference

Self-serve partner registration, API key management, webhook delivery, Open Banking consent access, and production upgrade workflow. Backend base path: /api/v1/partners · port 8080

Introduction

The CBA Partner Portal API enables fintech developers and third-party providers (TPPs) to self-register, receive sandbox access immediately, and manage their integration with the CBA platform. The frontend partner portal (partner-portal.vercel.app) is built on top of these endpoints.

Three-Principal Model

PrincipalAuth MethodHeaderScope
PublicNone—Registration and login only
Partner JWTHMAC-SHA256 JWT issued by CBA backendAuthorization: Bearer {token}All self-serve partner endpoints
ADMINKeycloak JWT (bank staff, ROLE_ADMIN)Authorization: Bearer {keycloak_token}Partner approval, rejection, and aggregate views
Two separate JWT systems. Partner JWTs are issued by the CBA backend using HMAC-SHA256 and are not Keycloak tokens. Admin endpoints require a valid Keycloak token with ROLE_ADMIN. The backend validates the token type before routing — passing a partner JWT to an admin endpoint will return 403.

Partner Status Lifecycle

SANDBOX → (submit application) → PENDING_REVIEW → (approved) → PRODUCTION
PENDING_REVIEW → (rejected) → SUSPENDED

Environments

EnvironmentStatusNotes

PRODUCTIONAfter admin approvalRequires a submitted PartnerApplication

Tier Limits (Rate Limiting)

TierRequests / minNotes

All rate-limited paths return X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset headers. A 429 Too Many Requests response includes Retry-After: 60.

Authentication

Partner JWTs are signed with HMAC-SHA256. The token carries these claims:

ClaimTypeDescription
subUUIDPartner user ID
emailStringPartner user email
roleStringDEVELOPER or ADMIN
orgIdUUIDOrganisation ID — used as path param in all org-scoped endpoints
orgNameStringOrganisation display name
statusStringCurrent org status: SANDBOX / PENDING_REVIEW / PRODUCTION / SUSPENDED
tierStringBASIC / PRO / ENTERPRISE
environmentStringSANDBOX or PRODUCTION
expUnix timestamp24 h from issuance

Using the token

Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ1dWlkIiwiZW1haWwiOiJkZXZAZmlu...
Tokens expire after 24 hours. Call POST /api/v1/partners/auth/login to obtain a fresh token. There is no refresh endpoint — just re-login.

API Keys

API keys are used for machine-to-machine access to protected CBA Open Banking APIs. Each key has a scope list and a tier that determines rate limits. The raw key value is returned exactly once at creation and is never retrievable again — the backend stores only a BCrypt hash with a 12-character display prefix.

Key format: cba_ + Base64URL(32 random bytes). Example: cba_Zm9vYmFyYmF6cXV4...
GET /api/v1/partners/{orgId}/api-keys List active API keys (hashed — raw value never returned)

Returns all active API keys for the organisation. The keyPrefix field shows the first 12 characters of the key for identification. The full key is never returned after creation.

Response 200

      "name": "Production Key",

      "active": true,
      "lastUsedAt": "2026-04-25T09:00:00Z",
      "createdAt": "2026-04-01T08:00:00Z"

}

Webhooks

Register HTTPS callback URLs to receive real-time event notifications. Payloads are signed with X-CBA-Signature: sha256={HMAC-SHA256(payload, secret)}. Your endpoint must return a 2xx status within 30 seconds or the delivery is marked failed.

Delivery Behaviour

  • 5 maximum attempts per delivery: backoff schedule 15 s → 60 s → 5 min → 30 min → 2 h
  • After 5 failures the delivery is marked FAILED — no further retries
  • Every delivery carries a unique X-CBA-Delivery UUID header for idempotency
  • The X-CBA-Event header contains the event type (e.g. PAYMENT.COMPLETED)

Signature Verification

# Python
import hmac, hashlib
def verify(secret: str, payload: bytes, header_sig: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), payload, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header_sig)

# JavaScript (Node)
const crypto = require('crypto');
function verify(secret, payload, headerSig) {
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(payload).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(headerSig));
}

Consents (Open Banking)

Partners can view and revoke Open Banking consents that were initiated using their orgId as the tppClientId. When a PSU authorises your TPP application via the CBA Open Banking API, set tppClientId = orgId in the consent creation request — this links it to your partner account.

Linking mechanism: the tppClientId field on OpenBankingConsent must equal the partner's orgId (UUID string). Consents created without this are invisible to the partner API.
GET /api/v1/partners/{orgId}/consents List all Open Banking consents linked to this partner

Returns consents where tppClientId = orgId, ordered by createdAt DESC.

Response 200

{

      "expiryDate": "2026-10-25T00:00:00Z",
      "createdAt": "2026-04-25T10:00:00Z"
    },
    {
      "id": "uuid",
      "consentId": "ob-d9e7f1b2...",

      "scopes": ["payments"],

Consent status values: AWAITING_AUTHORISATION · AUTHORISED · REVOKED

Revokes the consent immediately. The PSU's access via this consent is terminated. Returns 404 if the consent does not exist or if the tppClientId does not match orgId (prevents enumeration).
