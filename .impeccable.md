# Impeccable Design Context — CBA Backoffice (React)

## Design Context

### Users
Bank operations staff — tellers, loan officers, branch managers, and system admins — working at a desk during business hours in a formal financial institution context. They live in this interface for 6–8 hours a day processing customer transactions, loan applications, account operations, and compliance workflows. Speed and accuracy matter more than novelty. The interface must reduce cognitive load, not add to it.

**Jobs to be done:**
- Onboard customers and manage KYC workflows
- Process deposits, withdrawals, and inter-account transfers
- Approve and disburse loans; track repayment schedules
- Manage card operations, disputes, and settlement batches
- Run reports, configure system parameters, audit activity

### Brand Personality
**Trustworthy, clear, approachable.**

Banking is inherently intimidating. This backoffice tool should project calm authority — the kind that makes a teller feel competent and a customer-facing operation feel under control. Not cold or bureaucratic, not startup-casual. Think: a well-designed regional bank that actually cares about its staff experience.

**Emotional goal:** The interface should make users feel *capable*, not overwhelmed. Every screen should answer "what do I do next?" without requiring training.

### Aesthetic Direction
**Bold redesign** — same brand palette as foundation, but new typographic system, new layout density, new interaction patterns. This is clearly a new product generation, not just a React port.

**Theme:** Dark shell + white content cards. Dark sidebar (`#0a1628` area) and topbar reduce peripheral eye strain for desk workers. White card surfaces provide the reading contrast needed for dense financial data.

**Colour system — OKLCH:**
- App shell background: `oklch(10% 0.018 250)` — near-black, tinted toward navy
- Sidebar: `oklch(15% 0.028 250)` — slightly lighter, same navy tint
- Content cards: `oklch(99% 0.004 250)` — near-white, almost imperceptible cool cast
- Primary CTA: `oklch(28% 0.045 250)` — deep navy (maps to `#1e2833`)
- Primary text: `oklch(8% 0.020 250)` — near-black navy (maps to `#000314`)
- Accent: `oklch(72% 0.13 68)` — warm amber/gold; used sparingly for key status indicators and interactive focus states. Feels premium, not startup-y, and reads on both dark and light surfaces.
- Neutrals: tinted toward hue 250 at chroma 0.006–0.010 throughout

**Typography:**
- Display / headings / section labels: **Epilogue** (Google Fonts, variable) — geometric, confident, designed. Weights 500–700.
- Body / UI / data: **Geist** (Vercel open source) — purpose-built for information-dense interfaces, true tabular numerals (`font-variant-numeric: tabular-nums`), excellent at 12–14px.
- Type scale (fixed `rem`, not fluid — this is app UI not marketing):
  - `xs`: 0.75rem / 12px — table cell metadata, timestamps
  - `sm`: 0.875rem / 14px — table body, form labels, secondary text
  - `base`: 1rem / 16px — primary body, input values
  - `lg`: 1.125rem / 18px — section headings, modal titles
  - `xl`: 1.25rem / 20px — page titles
  - `2xl`: 1.5rem / 24px — KPI numbers, key metrics

**Anti-references (must NOT look like these):**
- Generic SaaS (Stripe/Linear) — no soft purples, no "everyone copies Linear" subtle border aesthetic
- Heavy enterprise (SAP/Oracle) — no dense grey toolbars, no nested table-within-table, no 1990s navigation trees
- AI startup aesthetic — no cyan gradients, no glowing cards, no neon accents on dark backgrounds
- Material Design — no elevation ripples, no Google component library feel

### Design Principles

1. **Data over decoration.** Every visual element must earn its place by making information clearer or an action more findable. Decorative elements that don't aid comprehension are removed.

2. **Calm authority.** The interface should feel stable and reliable. No animations that feel energetic or playful. Transitions convey state, not personality. Easing is always `ease-out-quint` — objects decelerate smoothly.

3. **Density with breathing room.** Financial data is inherently dense. The solution is not to spread it out (that wastes screen space) but to use spacing *hierarchically* — tight within groups, generous between groups. Table rows: 44px. Section gaps: 32–48px. Card padding: 24px.

4. **Approachable structure.** Clear section headings, visible affordances, never relying on hover-only disclosure for critical actions. A new teller on day one should be able to navigate without a manual.

5. **Amber as the single accent.** The warm amber (`oklch(72% 0.13 68)`) is used for: focus rings, active nav items, key status badges, and primary interactive highlights. It appears nowhere else. Its rarity is its power.

### Technical Constraints
- React + Vite 6, React Router v6, TanStack Query v5, Axios
- shadcn/ui components (owned code, not a library dependency)
- Tailwind CSS v4 (CSS-first config)
- TypeScript strict mode
- WCAG 2.1 AA minimum — all interactive elements keyboard-navigable, all text contrast ≥ 4.5:1 on respective backgrounds
- Tabular numerals throughout (financial figures must never reflow on update)
- `prefers-reduced-motion` respected — all transitions wrapped in `@media (prefers-reduced-motion: no-preference)`
